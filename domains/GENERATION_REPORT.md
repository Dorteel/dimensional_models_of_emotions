# Domain Model Generation Report

| Status | Models |
|---|---|
| Generated (`domains/<model>.ods` + `domains/<model>.yaml`) | `circumplex`, `pad`, `plutchik_model`, `vector_model` |
| Not generated: discrete, no quality dimensions | `eckman`, `plutchik`, `mikels` |

A model is generated when the sources document at least one quality dimension for it. Every undocumented value is marked rather than filled in:

| Missing value | ODS cell | YAML |
|---|---|---|
| Dimension or emotion definition | `undefined` | `"undefined"` |
| Dimension minimum/maximum | `unknown` | `null` |
| Dimension circularity | `unknown` | `null` |
| Model description (optional in the template) | empty | `""` |

Each missing item, with source references for investigating it, is listed in `domains/MISSING_DEFINITIONS.md`. That file is generated together with the models.

Generated by `domains/build_domain_models.py`; validated by `domains/validate_domain_models.py`.

## Inputs, template and YAML structure

| Item | Used | Note |
|---|---|---|
| Model lists | `sources/dimensional_model_overview.csv`, `sources/discrete_model_overview.csv` | `sources/domainmodels/` does not exist. |
| Coordinates | `sources/models/circumplex/standard_model.csv`, `sources/models/pad/standard_model.csv` | No coordinate files exist for other models. |
| Emotion definitions | `sources/emotions/emotion_dictionary.ods` | Verbatim; source and URL cited in each emotion's Notes. |
| Emotion concepts | `sources/emotions/emotion_catalogue.ods` | Every prototype resolves to a concept; prototype IDs equal catalogue concept IDs. |
| Template | `domain_model_template_with_notes.ods` | `domain_model_template.ods` (named in the task) no longer exists; this file has the same DomainModel layout. Opened as a template, never modified. |
| YAML structure | `ExportYAML` macro, `custom_domain_model_definition.ods` (Basic/Standard/Module1) | Port of the macro; quoting, numbers and IDs are produced by the macro's own `YAMLQuote`/`YAMLNumber`/`SafeID`. It reproduces the macro-exported `domains/yourdomainmodel2.yaml` byte-for-byte. |

**One extension of the macro's rules.** The macro accepts only numbers for Minimum/Maximum and only Yes/No for Circular. The port additionally accepts `unknown` and exports it as YAML `null`, so that unknown values are not replaced by defaults. Everything else is unchanged:
- definitions must be non-empty;
- coordinates must be numeric;
- coordinates must lie within the range when the range is known.

**The YAML is always derived from the saved ODS.** Re-exporting each ODS reproduces its YAML byte-for-byte.

## Ambiguities left unresolved

1. **Word forms are not merged.** Several prototypes are adjectives without definitions, while related nouns in the dictionary have them: angry/Anger, sad/Sadness, delighted/Delight, serene/Serenity, bored/Boredom, annoyed/Annoyance, frustrated/Frustration. They stay `undefined`; the related concepts are listed in `MISSING_DEFINITIONS.md` as leads only.
2. **Several definitions for one emotion.** The template holds one definition per emotion. No current prototype has more than one candidate. If one did, the generator would stop and ask for a researcher decision rather than pick one.
3. **Circumplex range.** The overview records one range per model row. Applying it to both dimensions is a reading of the source, noted in each dimension's Notes.
4. **PAD range.** Not documented. The coordinates are all ±1, but no range was inferred from them.
5. **`ground_truth`.** Copied into Circumplex's Notes as recorded; its meaning is not documented.
6. **Two Plutchik entries.** `plutchik_model` (dimensional) and `plutchik` (discrete) are kept separate. 32 emotions are tagged `plutchik` in `emotion_definitions.csv`, but none has an intensity value, so none became a prototype.
7. **`eckman`.** The spelling is preserved as recorded.
8. **Dataset dimensions.** EMOTIC and AffectNet in `sources/datasets.csv` are annotation dimensions of datasets, not models. They are listed only as investigation leads for the valence/arousal/dominance definitions.

## Completing a model

- **Preferred:** add the missing facts to `sources/` and rerun `python3 domains/build_domain_models.py`.
- **By hand:** edit a copy of `domains/<model>.ods`, replacing `undefined`/`unknown` with documented values and citing the source in Notes. Then run `python3 domains/build_domain_models.py --export <copy>.ods`. Regenerating overwrites `domains/<model>.ods`, which is why you edit a copy.

## Validation

```bash
python3 domains/build_domain_models.py
python3 domains/validate_domain_models.py
python3 sources/emotions/verify_emotion_tables.py
```

The validator reads each ODS back independently via LibreOffice and checks the following.

- **Model and dimensions:** name, notes, dimensions and ranges match the sources. Placeholders appear exactly where the sources lack a value, and never replace a documented one.
- **Prototypes:**
  - names, order and IDs match the coordinate file;
  - every coordinate is numeric and equals the source value, in both the ODS and the YAML;
  - every prototype resolves to a catalogue concept;
  - definitions are verbatim from the dictionary, or `undefined` exactly where the dictionary has none.
- **YAML:**
  - it has the ExportYAML structure;
  - it is valid: numeric coordinates within any documented range, `"undefined"` definitions and `null` range/circularity accepted;
  - it is equivalent to its ODS field by field, and a re-export reproduces it byte-for-byte.
- **`MISSING_DEFINITIONS.md`:** lists exactly the placeholder items, each with references.
- **The exporter:**
  - matches the macro-exported example;
  - rejects a text coordinate, an empty coordinate, an out-of-range coordinate, and a half-unknown range.
- **Untouched files:**
  - the template, the macro workbook, the OWL files, the emotion dictionary/catalogue and the example YAML files are unchanged (sha256);
  - git status shows no modified tracked file under `sources/`, `owl/`, `create_ontology.py` or `populate_ontology.py`.
